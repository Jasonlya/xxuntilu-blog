很多人一开始做自动化测试，都是写一堆脚本，能跑就完事。  
但真正成熟的测试工程，不只是“脚本能跑”，而是要做到：

- 可维护
- 可扩展
- 可复用
- 能稳定回归
- 能接入 CI/CD

这篇文章给一个更实际的思路：如何从 0 到 1，搭建一套 API 自动化测试框架。

---

## 1. 测试框架不是“写脚本”，而是“封装能力”

脚本可以解决某个单点问题，但框架解决的是一类问题。  
API 测试框架，需要对下面这些能力进行抽象：

- 请求构造
- 响应校验
- 断言封装
- 数据准备
- 环境切换
- 日志输出
- 失败分析
- 报告生成

如果不抽象，测试代码很快会变成一堆重复脚本，最后你会发现：

- 断言代码散落各处
- 环境参数到处写
- 接口变更导致大量重构
- 报告没法复用

---

## 2. 一个合理的框架结构

我通常建议从下面的结构出发：

```text
api-tests/
  config/
    env.yaml
    settings.py
  utils/
    http_client.py
    assert_utils.py
    data_loader.py
  tests/
    test_user_api.py
    test_order_api.py
  reports/
  conftest.py
